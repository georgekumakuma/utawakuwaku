# utawakuwaku v2 — 構想と設計、そしてこの先

> 「YouTube動画の好きな区間を"曲"として登録し、プレイリストで連続再生する」——
> この原点はそのままに、**歌枠のための、自分だけの音楽プレイヤー**へ発展させる。

---

## 1. コンセプトの再定義

v1 は「区間再生ができる便利ツール」だった。v2 では次の3つを約束する。

| 約束 | 意味 |
|---|---|
| **曲として扱う** | 区間は「動画IDと秒数」ではなく、曲名・アーティスト・歌い手・タグ・評価・再生回数を持つ「曲」。ライブラリとして横断検索でき、履歴が残り、キューに積める |
| **途切れない** | 2つのプレイヤーで次の曲を先読みし、クロスフェードで切り替える。曲間の黒画面・無音・読み込み待ちをなくす |
| **集める手間を一桁減らす** | 歌枠のコメント欄にあるタイムスタンプ（`1:23:45 曲名 / アーティスト`）をそのまま貼れば、全曲が区間付きで登録される。URLを貼って I / O キーで打刻するだけでも1曲10秒 |

Holodex（Musicdex）との違いは明確で、向こうは「みんなのデータベース」、こちらは「自分のキュレーション」。
データベースの規模で勝負せず、**個人の体験の質（正確な区間、途切れない再生、どこでも動く、誰のアカウントも要らない）** で上回る。

## 2. v2.0 で実現したこと

### 再生エンジン（`src/player/`）
- **2デッキ構成**: `Deck` ×2（YouTube IFrame Player）。区間終了の8秒前に次の曲を裏デッキへ読み込み、頭出しして待機。終了の `crossfade` 秒前から2つのデッキの音量を同時に変化させて切り替える
- **世代トークン**: 曲の切替・停止ごとにトークンを進め、古いタイマー・フェード・コールバックを無効化（v1.1 の信頼性改善をそのまま継承）
- **区間終了の二重保険**: `setInterval` による監視（バックグラウンドタブでも動く）＋ プレイヤーへ `endSeconds` を渡す
- **ENDED の真贋判定**: 曲切替直後の古い ENDED は無視するが、プレイヤーが実際に区間終端にいれば本物として扱う。終了位置を越えてシークして ENDED が来た場合は `endSeconds` なしで読み込み直して続きを再生（YouTube が「シーク後も endSeconds を守る」実装でも「守らない」実装でも正しく動く）
- **キュー**（次に再生）・シャッフル・リピート（全曲/1曲/なし）・再生速度・試聴（範囲指定で止まる）・自由再生（編集用）
- 再生できない動画はトースト通知のうえ自動スキップ（連続5回で停止）

### データ（`src/core/`）
- **IndexedDB** 永続化（localStorage フォールバック）。v1 の `utawakuwaku_playlist` / `utawakuwaku_playlists_v2` を起動時に自動移行
- **CSV 完全互換**: 旧ヘッダー `videoId,title,start,end,rating,article` をそのまま読み書き。拡張列（artist / singer / tags / note）はデータがあるときだけ末尾に付くので、旧版でも読める。列順の違い・ヘッダー無し・BOM・引用符内改行・余分な列に耐える
- **セットリスト解析**: 行頭/行末のタイムスタンプ、範囲（`1:00 ～ 2:00`）、番号付き、記号付き、`曲名 / アーティスト` 分割。終了が無い曲は次の曲の開始を終了にする
- **共有URL**: JSON → deflate 圧縮 → base64url（`#pl2=`）。旧形式 `#pl=` も読める
- **JSONバックアップ**: すべてのプレイリストと設定をひとつのファイルに
- 純粋ロジックは `node --test` のユニットテスト付き

### UI（`src/ui/`）
- 3ペイン（サイドバー / メイン / 編集・キューパネル）＋ プレイヤーバー。タブレットはパネルがオーバーレイ、スマホはドロワー＋ボトムシート
- **仮想スクロールの曲リスト**（数千曲でも軽い）。Ctrl/Shift クリックの複数選択、つまみドラッグの並べ替え、右クリックメニュー、行内の評価クリック、再生中のイコライザー表示
- **区間エディタ**: タイムライン上のドラッグ、I / O キーで現在位置を打刻、±5/±1/±0.1秒ボタン、開始・終了の試聴、「保存して次の区間」で同じ動画から続けて切り出し
- **追加モーダル**: URL（oEmbed でタイトル・チャンネル自動取得）/ セットリスト貼り付け（プレビューで曲名・アーティストを修正してから取り込み）/ CSV・JSON（ドロップ・貼り付け）
- **ライブラリ**（全リスト横断・重複排除・所属リスト表示）、**再生履歴**、**キュー**、**プレイリストバンク**（カード表示・曲数・読み込み済み表示）
- **コマンドパレット**（Ctrl/⌘+K）、キーボードショートカット一式、ヘルプ
- テーマ（ダーク/ライト/OS連動）とアクセントカラー、コンパクト表示
- Media Session API（ロック画面・イヤホン・メディアキー）、Screen Wake Lock、PWA（オフライン起動）

### 設計原則
1. **ビルド不要** — ES Modules をそのまま配信。`index.html` と `node server.js` だけで動く。Electron もそのまま
2. **ローカルファースト** — サーバーに何も送らない。データは端末の中。持ち出しは CSV / JSON / 共有URL
3. **YouTube 公式 API のみ** — ダウンロードや迂回はしない。広告・Premium の挙動は YouTube 側の仕様に従う（README 参照）
4. **旧版と互換** — CSV・localStorage・共有URLはすべて読める

## 3. ロードマップ（提案）

> v2.1 で実装済み: 同じ曲の別バージョン表示、タグ候補、リンク切れチェック（＋再生エラー時の自動マーク）、
> スリープタイマー（時間指定 / この曲の終わりで）、統計ビュー、曲ごとの音量補正。
> v2.2 で実装済み: 共有バンク（Googleスプレッドシートの「ウェブに公開」URL などを登録、紹介リンク、最新版で更新、作者が紹介する「みんなの共有バンク」一覧）。
> v3.0 で実装済み: シアターモード（オーロラ背景・FLIP で動画を移動・スマホの全画面プレイヤー）、アートワーク連動カラー、
> イントロクイズ、おまかせラジオ、配信アーカイブ（タイムライン表示・すき間から登録）、どこでも貼り付け/ドロップ、ミニプレイヤーのジェスチャー、View Transitions。

### v3 の設計メモ
- **動画の iframe は DOM を移動しない**: iframe は親を付け替えると読み込み直しになるため、シアターモードでは `.stage-video` を CSS の `position: fixed` にして、枠の位置（`--tv-x/y/w/h`）へアニメーションさせている。祖先に `transform`・`filter`・重なり順の文脈（`isolation` / `z-index`）があると固定配置が効かないので、シアター中はそれらを外す
- **アートワークの色**: `i.ytimg.com` のサムネイルを `crossOrigin="anonymous"` で読み、48×27 に縮小して画素を集計（`src/core/color.js`）。読めない環境では従来のアクセントカラーのまま。色は WCAG のコントラスト比 4.5 以上になるよう明度を調整
- **オーロラ**: 160px 幅の小さなキャンバスに放射グラデーションを描き、CSS で拡大して柔らかく見せる（軽い）。`prefers-reduced-motion` では静止
- **イントロクイズの試聴**は `_draft` の曲として再生するため、再生履歴・再生回数・OS のメディア表示には出ない（答えがばれない）
- 音声そのもの（波形・音量・BPM）は YouTube の iframe から取得できないため、オーロラは再生状態と曲の切り替わりにだけ反応する

### Phase 2 — 「集める」をもっと楽に
| 項目 | 内容 | 難易度 |
|---|---|---|
| ~~共有バンク~~ | v2.2 で実装（Googleスプレッドシート対応） | — |
| 同じ曲の別バージョン | 曲名が同じ（正規化後）区間をまとめ、「この曲を歌った配信一覧」を曲ページで見せる | 低 |

| 削除・非公開の検出 | oEmbed の 404/401 でライブラリ内の壊れた曲に印を付ける（一括チェック） | 低 |
| QR 共有 | 共有URLを QR コードで表示（スマホへ即転送） | 低 |

### Phase 3 — 「聴く」体験の深化
| 項目 | 内容 | 難易度 |
|---|---|---|
| 曲内マーカー | サビ・ハモリなどの位置を曲に付けて、ワンタップでジャンプ | 中 |
| 練習モード | A-B ループ回数指定・速度 0.5〜2x（速度は実装済み）・開始前カウントイン | 中 |
| スリープタイマー | 指定時間・この曲で止める | 低 |
| スマートプレイリスト | 「評価5以上」「タグ=バラード」「最近追加」などのルールで自動更新されるリスト | 中 |
| 統計 | よく聴く歌い手・曲・時間帯、合計再生時間 | 低 |
| 細かな調整 | 曲ごとのクロスフェード秒数、曲ごとの音量オフセット（配信によって音量差が大きいため） | 中 |

### Phase 4 — 「持ち運ぶ」
| 項目 | 内容 | 難易度 |
|---|---|---|
| クラウド同期 | ユーザー自身の GitHub Gist / Google Drive トークンで JSON を同期（サーバー不要のまま複数端末） | 中 |
| 差分マージ | 共有されたプレイリストを「置き換え」ではなく「無い曲だけ追加」で取り込む | 低 |
| i18n | UI の英語化（海外の VTuber ファン向け） | 中 |
| Electron | 自動更新・グローバルメディアキー・最小化時のミニプレイヤー | 中 |

### やらないこと（YouTube の仕組み上できない・やるべきでない）
- 音声の解析（波形表示・音量正規化・可視化）: iframe の音声には Web Audio からアクセスできない
- 歌詞表示: 権利上の問題。曲名から歌詞サイトへのリンクに留める
- 広告の除去・Premium の偽装: 公式 API の範囲外。README に挙動を明記するに留める
- Chromecast: iframe プレイヤーからは不可。将来「YouTube の再生リストとして書き出す」で代替

## 4. Holodex（Musicdex）との比較

| 観点 | Musicdex（無料） | utawakuwaku v2 |
|---|---|---|
| 対象 | 登録された VTuber・コミュニティ投稿の曲 | **任意の YouTube 動画**。切り抜き・ショート・自分だけの推しも |
| 区間の精度 | 投稿者依存 | **0.1秒単位**で自分で追い込める。試聴・微調整ボタン付き |
| 曲間 | 読み込みのたびに途切れる | **先読み＋クロスフェード** |
| データの所在 | 向こうのサーバー | **自分の端末**。CSV/JSON/URL で持ち出し自由 |
| アカウント | 必要（お気に入り等） | **不要** |
| オフライン | 不可 | UI は PWA でオフライン起動（再生は要ネット） |
| 取り込み | 手動フォーム | **セットリスト貼り付け一括**、URL + I/O 打刻 |
| 横断検索 | 強い（コミュニティDB） | 自分のライブラリ内のみ（Phase 2 で外部バンク購読により拡張） |
| 配信スケジュール・マルチビュー | ある | 対象外（コンセプト外） |
